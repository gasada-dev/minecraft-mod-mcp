# Устранение проблем Wayland и Hyprland

Это руководство описывает практические проблемы управления Minecraft Mod MCP на нативном рабочем столе Wayland. Команды используют Hyprland, Prism Launcher и Linux, но порядок действий и ограничения ввода применимы к другим композиторам Wayland и внешним лаунчерам.

## Проверяйте клиент несколькими сигналами

`get_minecraft_status().processAlive` сообщает, запущен ли процесс этим мостом. Если Minecraft запущен Prism или другим внешним лаунчером, ожидаемо значение `false`; в этом случае используйте `connected` вместе с указанным модом `pid`.

Инструмент статуса проверяет выбранный порт мода и очищает устаревшее соединение после неудачного heartbeat. При диагностике внешнего клиента проверяйте несколько независимых сигналов:

1. Найдите настоящий PID Java.
2. Подтвердите PID через `ps`.
3. Вызовите `ping`.
4. Прочитайте `get_player_info`.
5. Сделайте скриншот или проверьте текущий GUI.
6. Проверьте актуальные отметки времени в Minecraft `latest.log`.

Статус содержит фактические `pid`, `uptime`, `version` и `loader` мода. Предпочитайте эти значения первому найденному на машине Java-процессу.

## Найдите окно Wayland

Wayland не предоставляет глобальное управление окнами, как X11. В Hyprland используйте IPC композитора:

```bash
hyprctl clients -j | jq -c '.[] | { address, pid, class, title, workspace, focusHistoryID }'
```

Класс окна Minecraft при запуске или в некоторых состояниях LWJGL может быть пустым. Сопоставляйте PID и заголовок; после каждого перезапуска определяйте их заново, потому что старые процессы Prism и Java могут сосуществовать.

Не выбирайте первый процесс с именем `java`: Gradle daemons и выделенные серверы тоже используют Java. Полезная диагностика:

```bash
ps -eo pid,ppid,stat,lstart,cmd | rg '/java.*(org\.prismlauncher\.EntryPoint|minecraft)'
```

## Учитывайте модель процессов Prism

Prism обычно однопроцессный. Новый вызов AppImage может переслать запрос запуска существующему процессу Prism и завершиться; дочерний Java-процесс создаёт уже существующий Prism.

Следствия:

- `$!` команды AppImage может не быть PID Minecraft.
- Ожидание AppImage не обязательно покажет код завершения Minecraft.
- Перенаправленный вывод AppImage может содержать только предупреждения интерфейса Qt.
- После запуска нужно обнаружить и отслеживать новый дочерний Java-процесс.

Например:

```bash
PrismLauncher.AppImage --appimage-extract-and-run --launch "INSTANCE_ID" --server example.invalid
```

Это предупреждение относится к Qt-интерфейсу Prism и само по себе не доказывает сбой Minecraft или LWJGL:

```text
qt.qpa.plugin: Could not find the Qt platform plugin "wayland"
```

Prism может работать через XWayland, пока Minecraft использует отдельное окно GLFW.

## Что делает `press_key`

В современных версиях Minecraft `press_key` вызывает обработчик клавиатуры внутри процесса, а не событие клавиатуры ОС. Это работает для обычного игрового ввода, но может не вызывать каждый специфичный для загрузчика или нативный слушатель GLFW другого мода.

Если тесту нужно событие на уровне композитора, Hyprland `0.56` может направить его текущему PID Minecraft:

```bash
hyprctl dispatch 'hl.dsp.send_key_state({mods="", key="Up", state="down", window="pid:PID"})'
sleep 0.2
hyprctl dispatch 'hl.dsp.send_key_state({mods="", key="Up", state="up", window="pid:PID"})'
```

Это расширенный резервный вариант, не часть Minecraft Mod MCP. Синтаксис Hyprland различается между версиями.

При его использовании:

- Всегда отправляйте отдельные события нажатия и отпускания.
- Никогда не используйте PID после перезапуска.
- Записывайте PID цели и каждое отправленное событие.
- Подтверждайте ровно одно изменение состояния в игровом логе.
- Не смешивайте инъекцию композитора с переключателем `KeyMapping.consumeClick()` в очереди, если не требуется повторная активация.

## Разделяйте отпускание курсора, режим управления и фокус

Это разные состояния:

- `release_mouse` освобождает захват курсора GLFW.
- Режим управления MCP включает инструменты кликов, ввода и клавиатуры MCP.
- Настройка Minecraft паузы при потере фокуса определяет поведение после смены окон или рабочих столов.

Отпускание курсора само не меняет настройку паузы Minecraft. Автоматизация, которой нужны тики клиента без фокуса, должна отдельно учитывать конфигурацию Minecraft или тестируемого мода.

Включайте режим управления только на нужное время. Статус, игрок, мир и скриншоты безопаснее для пассивного наблюдения. Действия GUI и клавиатуры могут требовать режима управления; после них подтверждайте результат на стороне сервера, а не считайте локальный клик уже изменившим инвентарь.

## Безопасно переключайте рабочие столы

Перед тестом проверьте текущий рабочий стол и положение Minecraft:

```bash
hyprctl activeworkspace -j
hyprctl clients -j | jq -c '.[] | select(.pid == PID) | {pid,title,workspace}'
```

Если тесту нужна только потеря фокуса, предпочитайте семантическую команду композитора:

```bash
hyprctl dispatch 'hl.dsp.focus({workspace=2})'
```

Она не оставляет Minecraft нажатые `Super` или цифровую клавишу. Используйте настоящее сочетание `Super + number` только для воспроизведения маршрутизации клавиатуры.

После переключения проверьте тот же PID Java, вызовите `ping` и `get_player_info`, затем проверьте игровой лог на неожиданные клавиши. Если переключатель автоматизации меняет состояние непосредственно перед выходом, сначала исследуйте маршрутизацию ввода, а не классифицируйте событие как сбой рендеринга Wayland.

## Диагностика внезапных завершений

Логи Minecraft не объясняют каждый внешний `SIGTERM` или `SIGKILL`. Проверьте все доступные уровни около времени сбоя:

```bash
journalctl --since 'TIME-1min' --until 'TIME+1min' --no-pager
journalctl -k --since 'TIME-1min' --until 'TIME+1min' --no-pager
coredumpctl list --no-pager
```

Также проверьте:

- Minecraft `logs/latest.log`;
- Minecraft `logs/debug.log`;
- логи Prism и захваченный вывод игры;
- `hs_err_pid*.log`;
- логи композитора.

Типичные интерпретации:

- Java stack trace или отчёт загрузчика: сбой игры или мода.
- `hs_err_pid` или coredump: сбой JVM, нативной библиотеки или LWJGL.
- запись kernel OOM: завершение из-за нехватки памяти.
- чистый конец лога без последовательности shutdown: вероятный внешний сигнал.
- остановка мода или переключатель непосредственно перед выходом: вероятнее ввод или поведение приложения, не сбой композитора.

Если Prism уже работал, отслеживайте найденный дочерний Java-процесс напрямую: пересылающая команда AppImage не может дать код завершения игры.

## Контрольный список теста

1. Запишите версии композитора, лаунчера, Minecraft, загрузчика, мода и Java.
2. Запустите нужный экземпляр.
3. Найдите новый PID из `/api/status` и адрес окна Hyprland.
4. Подтвердите PID, `ping`, состояние игрока, скриншот и актуальность логов.
5. Входите в режим управления, только если это нужно действию.
6. Отправьте одно явное действие клавиатуры и подтвердите один результат.
7. Проверьте семантическое переключение рабочего стола до инъекции настоящего сочетания.
8. После смены фокуса снова проверьте PID, вызовы MCP и логи.
9. Сохраните все логи до перезапуска после сбоя.
10. Никогда не включайте в отчёты об ошибках аккаунты, токены доступа, приватные адреса серверов или содержимое чата.
